3. Tipos de forwarding

Você aprendeu um tipo.

Mas existem 3 principais:

Local Forwarding (-L)
ssh -L 8080:localhost:3000 user@host

Fluxo:

Seu navegador
    ↓
localhost:8080
    ↓ túnel SSH
Servidor remoto:3000

Uso:

acessar painéis internos
banco de dados remoto
dashboards
APIs privadas
Remote Forwarding (-R)
ssh -R 2222:localhost:22 user@host

Fluxo:

Servidor remoto
    ↓
porta 2222
    ↓ túnel
seu computador local

Muito usado para:

reverse shell
acesso reverso
NAT traversal
IoT
Dynamic Forwarding (-D)
ssh -D 8080 user@host

Cria um proxy SOCKS5.

Fluxo:

Aplicação
    ↓
SOCKS Proxy
    ↓ túnel SSH
internet pelo servidor remoto

Isso é praticamente uma mini-VPN.

COMUNICAÇÃO MAQUINA E UM SERVIDOR -------------

A forma mais fácil de entender a diferença entre eles é olhar para onde o tráfego entra e para onde ele vai.

1. Local Forwarding (-L)
O Local Forwarding pega uma porta da sua máquina local (onde você está digitando o comando) e a redireciona para um destino a partir da perspectiva do servidor SSH.

Como funciona: Você abre uma porta "X" no seu próprio PC. Qualquer programa seu que enviar dados para essa porta "X" terá o tráfego encapsulado pelo SSH, enviado até o servidor remoto, e o servidor remoto entregará esse tráfego ao destino final.

Caso de uso clássico: Você quer acessar um banco de dados (ex: MySQL na porta 3306) que está rodando dentro de um servidor na nuvem, mas o firewall do servidor bloqueia o acesso externo.

O Comando:

Bash
ssh -L 8080:localhost:3306 usuario@servidor-ssh
(Traduzindo: "Pegue a porta 8080 do meu PC local, mande pelo túnel e, quando chegar lá no servidor-ssh, entregue para o localhost:3306 dele mesmo"). Agora, se você conectar seu client de banco de dados em localhost:8080, estará acessando o banco do servidor seguro.

2. Remote Forwarding (-R)
O Remote Forwarding (também chamado de Reverse Tunneling) faz exatamente o oposto. Ele pega uma porta do servidor remoto e a redireciona de volta para a sua máquina local (ou para outro lugar que sua máquina acesse).

Como funciona: Você abre uma porta "Y" lá no servidor SSH na nuvem. Qualquer pessoa ou serviço na internet que acessar essa porta "Y" do servidor terá o tráfego enviado de volta pelo túnel SSH direto para uma porta na sua máquina local.

Caso de uso clássico: Você está desenvolvendo um site no seu PC (localhost:3000) e quer mostrar para um cliente. Como você está atrás do roteador da sua casa (NAT) e não tem IP público, o cliente não consegue te acessar. Você usa o -R para expor sua porta local através de um servidor público na nuvem.

O Comando:

Bash
ssh -R 9090:localhost:3000 usuario@servidor-publico
(Traduzindo: "Abra a porta 9090 no servidor-publico. Tudo o que chegar nela, mande de volta pelo túnel e entregue no localhost:3000 da minha máquina local"). Se o cliente acessar http://servidor-publico:9090, ele verá o site rodando no seu PC.

3. Dynamic Forwarding (-D)
O Dynamic Forwarding transforma o seu servidor SSH em um SOCKS Proxy. Ao contrário dos anteriores, você não define um destino fixo (como uma porta ou IP específicos).

Como funciona: Você abre uma porta local no seu PC. Qualquer aplicativo configurado para usar essa porta como proxy (como o seu navegador de internet) terá todo o seu tráfego web enviado para o servidor SSH, e o servidor SSH fará as requisições para a internet no seu lugar.

Caso de uso clássico: Você está conectado no Wi-Fi público de uma cafeteria e não confia na rede, ou precisa acessar um site que está bloqueado na rede local onde você se encontra, mas que o seu servidor remoto consegue acessar.

O Comando:

Bash
ssh -D 1080 usuario@servidor-ssh
(Traduzindo: "Abra a porta 1080 no meu PC como um proxy dinâmico"). Depois de rodar isso, basta ir nas configurações do seu navegador (Firefox, Chrome), ativar o proxy SOCKS v5 apontando para localhost:1080. Pronto, você estará navegando na web usando o IP do servidor remoto.
